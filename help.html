🚀 Quick start

  1. Click the Stepture icon and fill in Document Title, Tester, Environment, and your first Scenario, then Start Session.
  2. On the page, click Annotate & Capture on Page. A toolbar appears at the top.
  3. Toggle Annotate: On, draw a box/arrow/highlight/text/redaction, then click Capture.
  4. Add a description, an expected result, and mark Pass or Fail.
  5. Click ＋ Scenario to start another scenario (steps restart at 1).
  6. Open the popup and Export Word Log, or push to Azure DevOps.
You can also add a screenshot from a file or paste one (e.g. from Windows Snipping Tool) with Ctrl+V in the popup.
Capture (delay): use the ⏱ Delay button (3s / 5s / 10s) when you need to capture a hover menu, dropdown, or tooltip that closes on click — trigger it, open the menu, and it captures after the countdown.

🔗 Connect Azure DevOps

This step is optional — you only need it if you want to push bugs, test cases, or evidence to Azure DevOps. Open the popup during a session and click ⚙ ADO.

Common mistake: putting a path like Project\Team in the Project field. The project is only the single project name. "Team" is separate.

🔑 Create a Personal Access Token (PAT)

A PAT is a credential that lets Stepture talk to Azure DevOps on your behalf. You create it in ADO and paste it into Stepture. Treat it like a password.

  1. In Azure DevOps, click your profile icon (top-right) → Personal access tokens. (Or go to https://dev.azure.com/<your-org>/_usersSettings/tokens.)
  2. Click + New Token.
  3. Give it a name (e.g. "Stepture"), pick your organization, and set an expiration.
  4. Under Scopes, choose Custom defined, then find Work Items and check Read & write.
  5. Click Create, then copy the token immediately — ADO shows it only once.
  6. Paste it into the Stepture ADO settings and click Save.
Security: The PAT is stored only in your browser, never sent anywhere except your own Azure DevOps. Use the Clear button to remove it. Give it a sensible expiry and the minimum scope (Work Items Read & write).
If the connection is rejected even with the right scope: your organization may block PAT access via policy. Check Organization Settings → Policies, or ask your ADO admin.

🧩 Required fields (if a Bug or Test Case won't create)

Many ADO projects require certain fields on a Bug or Test Case. If a push fails with a "Rule Error" naming a field, you need to supply it.

  1. In ⚙ ADO settings, click Discover required fields — it lists every field with its exact reference name.
  2. Copy the reference names you need into Default Bug fields, one per line, as ReferenceName=Value.

Example

Custom.DefectType=Functional
Custom.CurrentEnvironment=4. UAT/Staging
Microsoft.VSTS.Common.Priority=2
Microsoft.VSTS.Common.Severity=3 - Medium
The reference name (before the =) has no spaces. The value (after the =) must match the dropdown option in ADO exactly, including spaces and capitalization.
Area / Iteration: use System.AreaPath and System.IterationPath (the "...Path" fields), not the "...Id" fields. Or set the Area Path in settings and tick "current iteration" when pushing a Bug.
Sign-off fields (User Story): to find the reference name for fields like "PO Ready" or the exact State values, set the Discover fields dropdown to User Story and click Discover. Use those names in your sign-off presets.

🎨 Annotation tools

  • Box — frame an area (the default tool).
  • Arrow — point at something.
  • Highlighter — semi-transparent marker; auto-uses yellow.
  • Text — click a spot and type a label; rendered with a white outline for legibility.
  • Redact — solid black box to permanently cover sensitive data before capture.

Use the color picker to change colors (drawing tools default to red, highlighter to yellow). Undo removes the last annotation.

❓ FAQ

Where is my data stored?

Everything stays in your browser. Nothing is sent anywhere except the Azure DevOps organization you connect to, using your own credentials, and only when you push.

Bug vs Test Case vs Attach — which do I use?

  • Create a Bug — files a defect with repro steps and inline screenshots.
  • Create a Test Case — turns your scenario steps into an executable test case (one per scenario; "All scenarios" makes several at once under one parent).
  • Attach to existing — uploads the whole Word log to a story/defect you already have.

The recording was lost — why?

Recordings are held in memory until you attach them. Attach promptly; don't close the tab with an unattached recording.

Can I edit a step after capturing?

Yes — click the ✎ icon on any step in the popup to edit its description, expected result, status, or actual result.

What did I push, and where?

Click 📋 Push history in the popup to see every Bug/Test Case/attachment with copyable links and IDs.
